# NovelFlow

เว็บแอปแปลนิยาย — วางลิงก์หรือวางเนื้อหาดิบ แล้วให้ AI แปลให้แบบสตรีมทีละย่อหน้า
ใช้ API Key ของคุณเอง ทำงานได้ทั้งเดสก์ท็อปและมือถือ

## เริ่มใช้งาน

```bash
npm install
npm run dev
```

เปิด http://localhost:3000 → กดไอคอนตั้งค่ามุมขวาบน → ใส่ API Key → วางลิงก์ → กด "แปลเลย"

## ตั้งค่า Supabase (ไม่บังคับ — ไม่ตั้งก็ใช้งานได้ แต่จะเก็บในเครื่องอย่างเดียว)

1. เปิด Supabase Dashboard → **SQL Editor** → **New query** → วางเนื้อหาจาก
   [`supabase/schema.sql`](supabase/schema.sql) → **Run**
2. ไปที่ **Authentication → Sign In / Providers** → เปิด **Allow anonymous sign-ins**
   (ถ้าไม่เปิด แอปจะขึ้นว่าเชื่อมคลาวด์ไม่ได้ และจะเก็บงานไว้ในเครื่องแทน)
3. ค่า URL / publishable key อยู่ใน `.env.local` แล้ว — ดูตัวอย่างที่ `.env.example`

> ⚠️ รหัสผ่าน database ที่เคยส่งผ่านช่องทางที่ไม่ปลอดภัย ควรรีเซ็ตที่
> **Settings → Database → Reset database password** โปรเจกต์นี้ไม่ได้ใช้รหัสผ่านนั้นเลย
> (ใช้แค่ publishable key ซึ่งปลอดภัยเมื่อเปิด RLS ตาม schema แล้ว)

## แนวคิดเบื้องหลังคุณภาพงานแปล

- **ดึงเนื้อหาแบบหลายชั้น** — ลองจาก selector ของ CMS นิยายที่พบบ่อยก่อน แล้วค่อยใช้
  Mozilla Readability และสุดท้ายเลือกบล็อกที่ข้อความหนาแน่นที่สุด รองรับ charset
  GBK / Big5 / Shift_JIS ของเว็บจีนและญี่ปุ่น
- **รอบจับคำศัพท์ก่อนแปล** — AI อ่านตอนนั้นแล้วดึงชื่อตัวละคร สถานที่ ยศ ท่าไม้ตาย
  ออกมาเป็นคลังคำศัพท์ที่ล็อกไว้ ทุกชิ้นที่แปลหลังจากนั้นถูกบังคับให้ใช้คำเดียวกัน
  แก้เองแล้วสั่งแปลใหม่ได้
- **ตัดเป็นชิ้นตามย่อหน้า** — ไม่เคยตัดกลางย่อหน้า แต่ละชิ้นได้เห็นท้ายชิ้นก่อนหน้า
  ทั้งต้นฉบับและคำแปลเพื่อความต่อเนื่องของน้ำเสียง
- **จับคู่ย่อหน้าแบบ 1:1** — ใช้ marker `[[n]]` ทำให้เทียบต้นฉบับทีละย่อหน้าได้
  และรู้ทันทีว่าย่อหน้าไหนตกหล่น (มีปุ่ม "แปลที่ค้าง" ให้เก็บตก)
- **กฎเฉพาะภาษาไทย** — ห้ามใส่ ครับ/ค่ะ ในบทบรรยาย, เลี่ยงสำนวนแปลแข็ง ๆ
  อย่าง "การที่" หรือ "ถูก" พร่ำเพรื่อ, เลือกสรรพนามให้คงที่ทั้งตอน

## สถาปัตยกรรม

```
src/app/api/extract    ดึง HTML + แกะเนื้อหา (ทำฝั่งเซิร์ฟเวอร์ เลี่ยง CORS, มีกัน SSRF)
src/app/api/translate  สตรีม SSE ต่อไปยังผู้ให้บริการ AI ด้วยคีย์ของผู้ใช้
src/lib/prompt.ts      system prompt ของนักแปลวรรณกรรม
src/lib/chunk.ts       ตัดชิ้น + parse marker ระหว่างสตรีม
src/lib/translator.ts  ตัวควบคุมฝั่ง client (แปลขนาน 3 ชิ้น)
src/lib/repo.ts        local-first: เขียน IndexedDB ก่อน แล้วซิงก์ขึ้น Supabase
```

**API Key ไม่ถูกเก็บลงฐานข้อมูล** — อยู่ใน localStorage ของเบราว์เซอร์
เซิร์ฟเวอร์รับมาเพื่อส่งต่อไปยังผู้ให้บริการ AI ในคำขอนั้นแล้วทิ้งทันที

## ข้อควรทราบ

- เว็บที่โหลดเนื้อหาด้วย JavaScript หรือมีระบบกันบอทจะดึงไม่ได้ — ให้คัดลอกเนื้อหามาวางแทน
- ควรใช้กับงานที่คุณมีสิทธิ์อ่าน/แปล และเคารพเงื่อนไขการใช้งานของเว็บต้นทาง

## Deploy

แอปนี้ deploy ได้เลย ไม่ต้องแก้โค้ด แต่ **ต้องรันบน Node runtime จริง**
เพราะ `src/lib/fetch-page.ts` ใช้ `node:dns` / `node:net` กัน SSRF และ extractor ใช้ jsdom
→ **Cloudflare Workers/Pages ใช้ไม่ได้** ถ้าไม่รื้อโค้ดส่วนนี้

### แนะนำ: Vercel (ฟรี)

```bash
git init && git add -A && git commit -m "initial commit"
gh repo create webnovel --private --source=. --push
```

จากนั้นที่ vercel.com → New Project → เลือก repo → ใส่ Environment Variables 2 ตัว
(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`) → Deploy

- `maxDuration = 300` ที่ตั้งไว้ใน `/api/translate` ตรงกับเพดานของ Vercel Hobby พอดี
- Hobby ใช้ได้เฉพาะงานที่ไม่ใช่เชิงพาณิชย์ ถ้าจะหารายได้ต้องขึ้น Pro ($20/เดือน)

### หลัง deploy อย่าลืม

1. Supabase → **Authentication → URL Configuration** → เพิ่มโดเมนจริงใน
   **Site URL** และ **Redirect URLs** ไม่งั้นลิงก์เข้าสู่ระบบทางอีเมลจะเด้งกลับมาที่ localhost
2. ทดสอบดึงลิงก์จากเว็บจริงอีกรอบ — เว็บนิยายบางแห่งบล็อก IP ของ datacenter
   ทำให้ดึงบน production ไม่ผ่านทั้งที่บนเครื่องตัวเองผ่าน (ยังใช้โหมดวางข้อความได้)
